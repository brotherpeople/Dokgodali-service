# 11/09 피드백 반영 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `reference/Feedback1109.md`의 배송 예약 폼·관리자 화면 피드백을 반영하고, 신청 내용을 `reference/1-2. 대량등록_엑셀업로드_김선영_261005.xlsx` 형식으로 내보낼 수 있게 한다.

**Architecture:** 폼(`dokgodali-delivery.html`)과 관리자 화면(`dokgodali-schedule.html`)은 지금 구조를 유지한다. 계산 로직은 Node로 테스트할 수 있게 작은 JS 파일로 뺀다. 지금 있는 `dokgodali-delivery-pricing.js`와 같은 UMD 형식이다. 수정 이력은 새 테이블 `request_revisions`에 쌓고, 사진은 Supabase Storage에 올린다.

**Tech Stack:** 정적 HTML/JS, Supabase(Postgres RPC, Storage), Daum 우편번호 서비스, SheetJS(vendor), `node --test`

**Spec:** `reference/Feedback1109.md` (최우선 기준: `수정사항.md`)

## Global Constraints

- 작업 브랜치: `dev`에서 `feature/feedback-1109`를 따서 진행한다. 한국어 파일만 수정하고 `-en.html`은 나중에 따로 맞춘다.
- 규격 초과: 가로+세로+높이 합 **140cm 이상** 또는 한 변 **80cm 이상**, 박스당 €20 (`Pricing.RATES.oversize`)
- 중량 초과: 실중량 **20kg 이상**, 박스당 €20 (`Pricing.RATES.overweight`)
- 바퀴 달린 가방 핸들링 비용: €15 (`Pricing.RATES.carrierHandling`). 이 키 이름은 바꾸지 않는다.
- 고객 수정은 **견적서 발행 전까지만** 가능하다. 이미 구현되어 있는 `quote_issued_at` 잠금을 그대로 쓴다.
- 배터리·의약품 감지는 **경고만** 한다. 다음 단계로 넘어가는 것을 막지 않는다.
- 엑셀 내보내기는 26열(A~Z)이고 헤더 문구는 샘플 파일과 똑같이 쓴다. 품목 1개가 1행이다.

## Review Focus

1. 수정 링크로 **기존 신청**(새 칸이 없는 옛 payload)을 열어도 폼이 깨지지 않아야 한다. 새 칸은 빈 값으로 채운다. 담당: Task 6, 9, 10
2. 소수 치수(23.5cm)는 요금 계산에서 1cm 단위로 올린다(24cm). 경계값 139.5cm 합계는 140으로 올라가서 초과로 판정된다. 담당: Task 1
3. 품명 키워드가 단어의 일부에만 걸리면 오탐이다(예: `Escalade`에 `scale`). 단어 경계로 매칭한다. 담당: Task 8
4. 엑셀 내보내기에서 빈 칸 규칙(`-` 또는 `.`)이 샘플과 같아야 한다. 업로드할 때 오류가 나지 않게 하기 위해서다. 담당: Task 11
5. 사진 업로드 실패(용량 초과·네트워크 오류)가 신청 제출을 막으면 안 된다. 실패하면 URL을 직접 입력하는 칸이 남아 있어야 한다. 담당: Task 4
